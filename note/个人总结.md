## 核心贡献1：数据模型优化

重点：

Copy-On-Write（读共享/写复制）

为什么这样做：

编辑器图层很多。

如果每个节点都完整复制：

- 内存占用非常大
- Wasm 数据交换成本高

优化：

- 默认属性共享
- 修改时再复制

收益：

- 降低内存占用
- 提高 C++ / Wasm 数据交换效率

---

## 核心贡献2：undo/redo 重构

之前：

业务手动 commit。

问题：

- 容易遗漏
- 业务侵入严重
- 维护成本高

优化：

模型内部自动收集变更。

收益：

- 降低业务复杂度
- 提高可维护性
- undo/redo 更稳定

---

## 核心贡献3：超大画布导出优化

问题：

2W+ 画布导出：

- Wasm 内存溢出
- 浏览器卡死
- 大 bitmap 分配失败

解决：

- 分块渲染
- Worker 合成
- 主线程分段导出

收益：

- 提升超大尺寸导出稳定性
- 降低浏览器崩溃概率

---

## 核心贡献4：图层性能优化

重点：

- hit-test
- 对齐检测
- 图层检索
- 虚拟列表

优化：

- 减少无效 DOM
- 优化图层查找
- 降低高频交互卡顿

收益：

海量图层下依然保持流畅。

---

## 核心贡献5：Electron + Node Addon

问题：

JS ↔ Wasm 大数据交换性能差。

优化：

将核心逻辑迁移到 Node Addon。

收益：

- 减少跨语言数据拷贝
- 提高复杂绘图性能
- 提升桌面端交互响应

## 核心贡献6：多平台适配

# 二、动态路由 / AI生成组件 / 低代码问题

## 动态路由怎么实现

本质：

URL -> Route Config -> Component

React Router：

内部维护：

```ts
const routes = [
  {
    path: "/home",
    component: Home,
  },
];
```

浏览器 URL 变化：

- history.pushState
- popstate

重新匹配 route。

最终渲染对应组件。

---

## React Router 本质

React：

路由也是组件。

例如：

```tsx
<Route path="/home" element={<Home />} />
```

内部：

- context
- route tree
- 动态匹配

最终控制：

渲染哪个 React 组件。

---

## 低代码平台核心是什么

核心：

Schema 驱动。

不是直接存 React JSX。

而是：

```json
{
  "type": "Button",
  "props": {
    "text": "登录"
  }
}
```

页面本质：

JSON 数据。

---

## 用户输入生成组件怎么实现

### 第一步：AI 理解用户输入

例如：

用户：

“生成一个登录页面”

AI：

输出 Schema：

```json
{
  "type": "Page",
  "children": [
    {
      "type": "Input"
    },
    {
      "type": "Button"
    }
  ]
}
```

---

### 第二步：Renderer 渲染

Renderer：

```ts
render(schema);
```

内部：

```ts
Button -> ReactButton
Input -> ReactInput
```

最终：

Schema -> React组件。

---

### 第三步：编辑器状态管理

整个页面：

本质：

PageSchema。

编辑：

其实就是修改 JSON。

---

## AI 修改某个组件怎么实现

不能把整个页面传给 AI。

原因：

- token 太大
- 成本太高
- 上下文污染

---

## 正确做法

只传当前选中的节点。

例如：

```json
{
  "id": "button_1",
  "type": "Button",
  "props": {
    "text": "登录"
  }
}
```

用户：

“改成红色”

AI：

返回：

```json
{
  "props": {
    "color": "red"
  }
}
```

然后：

merge patch。

---

## 更高级方案

JSON Patch：

```json
{
  "op": "replace",
  "path": "/props/color",
  "value": "red"
}
```

优点：

- 数据量小
- 更稳定
- 更适合 AI 编辑器

---

主要使用：

- 泛型

- 类型约束

项目中：

- API 类型约束

提升：

- 可维护性
- 重构安全性
- 团队协作效率

---

## 箭头函数和普通函数区别

不只是 this。

重点：

### 1. 箭头函数没有自己的 this

this 来自外层作用域。

### 2. 没有 arguments

### 3. 不能作为构造函数

不能 new。

### 4. 没有 prototype

## JS 单线程怎么实现异步

JS 主线程是单线程。

异步能力：

由：

- 浏览器
- Node runtime

提供。

例如：

- 定时器
- 网络请求
- IO

完成后：

回调进入 EventLoop 任务队列。

---

## 宏任务

例如：

- setTimeout
- setInterval

---

## 微任务

例如：

- Promise.then
- queueMicrotask

---

## requestAnimationFrame

浏览器渲染前执行。

适合动画。

---

## WebWorker

JS 可以开启独立线程。

适合：

- 大计算
- 图像处理
- 编辑器大任务

避免阻塞主线程。

---

## Promise 有哪些状态

正确：

- pending
- fulfilled
- rejected

---

## Promise.all 本质

内部：

计数器。

每个 promise 完成：

```ts
count++;
```

当：

```ts
count === promises.length;
```

统一 resolve。

任何一个 reject：

直接 reject。

---

## 原型链是什么

对象查找属性：

先查自身。

没有：

沿：

```ts
[[Prototype]];
```

向上查找。

最终：

```ts
Object.prototype -> null
```

---

## 判断属性属于自身还是原型链

正确：

```ts
Object.hasOwn(obj, key);
```

或者：

```ts
obj.hasOwnProperty(key);
```

---

## Object 和 Map 区别

### Object

key：

默认：

- string
- symbol

适合：

普通对象。

---

### Map

key：

可以是任意类型。

并且：

- 插入顺序稳定
- 更适合频繁增删
- API 更完整

---

## 重排和重绘

正确：

重绘性能更好。

---

## 重排（Reflow）

例如：

- width
- height
- layout

特点：

会重新计算布局。

成本高。

---

## 重绘（Repaint）

例如：

- color
- background

特点：

不影响布局。

性能更好。

---

## transform 为什么性能好

transform：

通常：

不触发布局。

很多情况下：

直接 GPU 合成。

适合动画。

---

## 为什么频繁 setState 性能差

因为：

setState：

会触发：

- diff
- reconciliation
- 渲染更新

高频更新：

容易：

- 主线程阻塞
- 页面掉帧

编辑器场景：

通常不会所有状态都走 React。

而是：

- React 管 UI
- 核心渲染自己控制
